LocaleProof · Unity Editor tool · Available on the Unity Asset Store

Did everything migrate correctly? Verified. Every imported key. Every cell.

LocaleProof moves your I2 Localization export into Unity String Tables — and then checks the result against your source, cell by cell. It is a verification tool that happens to convert, not a converter that hopes for the best.

3 · Import — through Unity's own importer

String Table Collections are created or reused, Locales are set up, and the CSV goes in through the Localization package's importer. The plural-tag value goes in exactly as it was, and stays flagged for your review. The font term never enters a String Table.

What LocaleProof catches

What moves, what is flagged, what stays behind

Sorted before anything is written. The same eight sample terms, in the three groups the tool reports.

Moved

  • Default/Title Text
  • Menu/Start Text
  • Menu/Options Text
  • Menu/Quit Text
  • Shop/Price Text
  • Shop/SoldOut Text

Text terms, every language column you map, categories as separate tables or one. Written to the generated CSV and imported into your String Tables.

Moved unchanged + flagged

  • Hud/Points plural tag, parameter token

Values with I2 plural tags or {[PARAMETER]} tokens are carried across exactly as they are and listed for review. They are not rewritten into Smart Strings, because that mapping is not one-to-one.

Not moved

  • Ui/HeaderFont Font

Non-text terms — Font, Texture, Sprite, Atlas, Sound, Prefab. A String Table holds strings, so these stay behind, and you know before the first byte is written.

Requirements and scope

  • The com.unity.localization package (which itself brings in com.unity.nuget.newtonsoft-json).
  • I2 Localization is not required in the project you migrate into. LocaleProof reads only the CSV you exported yourself; it never reads I2's own files.
  • Out of scope: replacing I2 components on scenes and prefabs; migrating non-text terms; rewriting plural tags or parameter tokens into Smart Strings; language headers with a language code in brackets, such as English [en].
  • Rollback removes only the generated files recorded in the manifest. String Table Collections and Locales you created are never deleted.
